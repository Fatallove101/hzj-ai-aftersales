# 跨境售后 AI 话术助手 · 本地演示（111）

> 场景：你是汉正街一家服装跨境商户的客服。客户发来一段外文消息，你不知道怎么回。
> 这个工具**自动读取屏幕上的对话**，识别客户意图/情绪/紧急度，检索售后知识库，
> 生成 3 条候选话术（带合规校验和来源引用），你**点一下复制**就能发出去。

---

## 一、30 秒跑起来

双击 **`启动.bat`** → 浏览器会自动打开 <http://127.0.0.1:8799/>

不想用鼠标，也可以在 PowerShell 里跑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File server.ps1 -Port 8799
```

**零依赖**：不需要装 Python、不需要装 Node、不需要管理员权限。
只用到了系统自带的 PowerShell 5.1 + Windows 内置 OCR。

## 二、界面怎么用

界面上有**三种输入方式**，都汇入同一条处理管线，随便挑一种：

| 方式 | 操作 | 适用场景 |
|---|---|---|
| **① 自动读屏** | 点「▶ 开始自动读屏」→ 在弹窗里选中你的客服窗口 → 之后自动工作 | 日常坐席，手不用离开键盘 |
| **② 粘贴截图** | 在左侧预览框按 `Ctrl+V`，或把图片拖进来 | 临时用一下 |
| **③ 直接输入文本** | 把对话粘进文本框 → 点「分析并生成话术」 | **最快、最准，推荐日常优先用这个** |

点「**填充演示样本**」可以一键塞入一段西班牙语投诉，立刻看到完整效果。

生成之后：
- 每条候选话术带**风格标签**（安抚致歉 / 专业答疑 / 营销促单 / 纠纷调解 / 合规告知）
- 右上角语言选择器决定「复制」时复制哪种语言
- **★ 推荐**标记的那条是系统认为最该用的
- 底部 **采纳 / 修改后采纳 / 忽略** 会写进 `logs/qa_logs.jsonl` —— 这就是「数据闭环 Agent」的原料
- 点右上角「**数据闭环**」看采纳率统计

## 三、你提的方案 vs 我的建议

你说的方案是：**截图 → 发给 AI → 拿话术 → 复制回对话**。

这个思路是对的，**方向完全正确**——先跑通、先上线、先拿到真实反馈，比什么都重要。
但纯"手动截图发出去"有三个硬伤，所以我把主路径做成了**自动读屏 + 粘贴**：

| 问题 | 手动截图发出去 | 本 demo 的做法 |
|---|---|---|
| **慢** | 每次都要截图、切窗口、上传、等结果。客户已经在等了 | 自动读屏：画面一变就分析，话术先于你意识到需要它而出现 |
| **识别不准** | 小字、浅色底、外文，视觉模型容易读错；错一个词话术就跑偏 | 用 Windows 内置 OCR，**实测 258 字全对**；且你能在输入框里改 |
| **隐私** | 整张截图（可能带客户姓名、地址、旁边的窗口）传到云端 API | 截图**不出本机**，只有识别出的文字进入分析。云端只收到文本 |

**所以更优的顺序是：粘贴文本 > 自动读屏 > 手动截图。**
本 demo 三种全做了，你可以自己对比体验。

## 四、升级路径（这是重点）

这个 demo 的真正价值不是它现在能做什么，而是**它把升级路径铺平了**。四级递进：

```
第 1 级  ★ 你现在的位置：本地规则引擎
         截图/粘贴 → 本机 OCR → 本地规则分析 → 候选话术
         成本 0，不用注册任何账号，离线可跑
                │
                ▼
第 2 级  ★ 接入千帆（下一步）
         把 pipeline.ps1 里的「翻译」和「话术生成」两步换成千帆 API 调用，
         意图识别和合规校验可以保留本地（更快更便宜）
         收益：话术质量从"模板级"跃升到"大模型级"，多语言回译真正可用
                │
                ▼
第 3 级  ★ 剪贴板/快捷键（比截图更好的自动读取）
         听剪贴板或全局快捷键，按一下就读当前选中的对话文本
         收益：准确率 100%（是文字不是图片）、比 OCR 快、token 便宜
                │
                ▼
第 4 级  ★ 浏览器扩展 / 直接对接客服软件（终极形态）
         TikTok Shop、Amazon 卖家后台都是网页，Chrome 扩展能直接读页面 DOM，
         侧边栏出话术，一键插入输入框 —— 零复制粘贴
         收益：这是"真接入"，也是申报书里写的最终形态
```

**为什么第 4 级比"对接服务软件"更容易**：跨境电商的客服后台绝大多数是**网页**，
DOM 抓取比逆向桌面客户端容易一个数量级。先做扩展，桌面客户端留到最后。

## 五、做网页还是做软件？

**结论：做网页（Web 应用），不做桌面软件。** 具体形态是「**本地 Web 服务 + 浏览器界面**」：

```
浏览器界面（web/）
      │  HTTP → 127.0.0.1:8799
      ▼
本地服务（server.ps1：静态文件 + /api/analyze + /api/ocr + /api/feedback）
      │
      ▼
引擎（engine/：OCR · 知识库 · 7-Agent 管线）
```

注意它**不是"一个 html 文件"**，必须有后端。因为：

1. **密钥安全**：千帆的 API Key 绝不能放在浏览器里。纯前端网页一发布，任何人按 F12 就能拿走你的密钥刷你的额度。
2. **跨域限制**：浏览器直连千帆 API 会被 CORS 拦截，必须由本地服务中转。
3. **本地能力**：Windows OCR 只能在本地调，浏览器做不到。

**为什么是网页而不是桌面软件**：

| 理由 | 说明 |
|---|---|
| 与申报书一致 | 申报书 4.1 写的就是「轻量化 Web 坐席客服工作台，适配电脑端快速操作」 |
| 切中真实痛点 | 申报书 2.2 列了「中小商户数字化接受度偏低」——让商户**下载安装一个 exe** 是巨大阻力，发个链接就能用才是零门槛 |
| 商业模式要求 | 申报书 6.2 是 SaaS 订阅 + 按效付费 + 政企推广。**SaaS 只能是 Web**，桌面软件没法按坐席订阅 |
| 升级平滑 | 开发期跑在 `127.0.0.1`，将来把 server.ps1 搬到云上就是完整 SaaS，前端一行不用改 |

将来如果确实需要桌面版，按申报书 1.3 的定位，用 **DuMate 做轻量化桌面辅助插件**作为补充，而不是主路径。

这个 demo 故意把**能真做的都做成真的**，做不了的明确标注：

### ✅ 真实实现（不是 mock）

| 模块 | 说明 |
|---|---|

| **合规校验** | **真实执行** `data/compliance_rules.csv` 里的 25 条正则规则，含 `match_mode` 两层逻辑 |
| **术语库** | 真实读 46 条服装跨境术语（中英西德法），真实命中（实测 `vestido→连衣裙`、`mancha→污渍`） |

### ⚠️ 规则近似（接入千帆后替换）

| 模块 | 现状 | 替换方式 |
|---|---|---|
| **翻译** | 本地只能做术语级命中，**不做整句翻译**。界面会明确提示"本地演示未接入翻译模型" | 换成千帆翻译 Agent（`prompts/01`） |

## 七、自检（改完东西一定要跑）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\selfcheck.ps1
```

三部分检查：

1. **模板合规自检** —— 126 条模板话术 × 25 条真实规则，看有没有自己踩雷
2. **行为用例回归** —— 7 个场景（含对抗样本）验证意图/情绪/紧急度/覆盖度/转人工/语言
3. **合规闸门单元测试** —— 26 条故意违规的话术，验证拦截能力与误杀率

**当前状态：全部通过。**

这套自检不是摆设——开发过程中它**真实抓到了 4 类缺陷**：

| 抓到的缺陷 | 后果 | 修法 |
|---|---|---|
| 规则 R018/R019（欧盟14天告知、德国撤回权）误写成违规型正则 | **任何提到"退货/退款"的合规话术都会被误杀，误杀率 100%** | 引入 `match_mode`：`violation`（正则可靠）vs `obligation`（只能模型判） |
| 规则 R008 用了裸的 `第一` | "我们会**第一时间**告知您"被当成绝对化用语 | 收紧为 `第一品牌\|全国第一\|销量第一` 等 |
| 规则 R016 用了裸的 `地址是` | "请确认收件**地址是**否正确"被当成泄露隐私 | 收紧为必须匹配到具体值（号码/门牌） |
| 话术模板里出现"银行**卡号**、密码、验证码"字样 | 反诈提醒本身被安全规则拦截 | 改写为"任何敏感支付信息" |

> 顺带发现一个隐蔽工程问题：PowerShell 的 `Sort-Object` **不是稳定排序**，
> 只按一个键排会让同分候选随机换位，导致**同一个输入两次运行推荐不同的话术**。
> 已改为带原始序号做次级排序键，保证确定性——这对需要可审计的合规系统是硬要求。

## 八、已知限制（都是有意为之，不是 bug）

| 限制 | 说明 | 解决路径 |
|---|---|---|
| **OCR 会读到界面文字** | 截图里的标题栏、输入框提示（如 "Type a message..."）也会被读出来 | 识别结果会填进输入框，**你可以手动删掉多余的行**再分析；或升级做区域框选 |
| **多语言 OCR 只支持中/英** | 本机装了 `en-US` 和 `zh-Hans-CN` 语言包。西/德/法文字靠英文引擎勉强识别 | 在 Windows「语言和区域」里安装对应语言包即可，装完重启服务自动生效 |
| **OCR 语言是"择优"不是"合并"** | 中英混排的截图会挑一个字多的语言跑 | 升级为多语言结果合并去重 |
| **话术模板是固定文案** | 14 个意图 × 3 风格，不支持任意品类/场景 | 接千帆话术生成 Agent |
| **西语候选话术覆盖不全** | 只有部分模板带西语，其余回退英文并给提示 | 接千帆翻译 Agent 自动回译 |

## 十、改代码前必读（踩过的坑）

**⚠️ 编辑 `*.ps1` 后必须把文件存成「UTF-8 带 BOM」。**

PowerShell 5.1 读取 `.ps1` 时，如果文件没有 BOM，会按系统 ANSI 代码页解析。
中文会变成乱码，进而**破坏字符串引号配对，导致整脚本语法错误**：

```
+   Write-Host ("  Windows OCR 鍙敤璇█锛? + ($ocrLangs -join ', '))
Unexpected token 'Windows' in expression or statement.
```

救急命令：

```powershell
$b = New-Object System.Text.UTF8Encoding($true)
Get-ChildItem -Recurse -Filter *.ps1 . | ForEach-Object {
  $t = [System.IO.File]::ReadAllText($_.FullName, (New-Object System.Text.UTF8Encoding($false)))
  [System.IO.File]::WriteAllText($_.FullName, $t, $b)
}
```

HTML / CSS / JS / CSV **不需要** BOM —— 它们的编码由 HTTP 头或 `-Encoding UTF8` 显式指定。

## 十一、下一步怎么接千帆

改动集中在 `engine/pipeline.ps1` 的两处，其余全部不动：

1. **翻译**（现在的 `Get-LanguageGuess` + 术语命中）
   → 调千帆，用 `prompts/01-翻译Agent-系统提示词.md`，拿回 `translated_text`
2. **话术生成**（现在的 `Get-CandidateTemplates` 模板）
   → 调千帆，用 `prompts/04-话术生成Agent-系统提示词.md`，
   把 `retrieval.evidence` 作为上下文注入，拿回 `candidates[]`

**建议保留在本地的**：OCR、合规正则第一层、覆盖度判定、转人工规则。
理由：这些是确定性的、对延迟敏感的、且涉及安全 —— 放本地更快、更便宜、更可控。
**把模型用在它真正擅长的地方**：理解语言、判断语义、生成文本。

对接所需的完整配置见 `../04-千帆AppBuilder搭建实施手册.md`。
