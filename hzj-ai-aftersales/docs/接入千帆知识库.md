# 接入千帆知识库（MCP）

> 本文档对应 `v0.21.0` 起的可插拔知识源。
> 本地 CSV 知识库**现在就能用**；接千帆是「换个数据源」，管线不用改。

---

## 一、为什么要做成可插拔

管线里的检索**只认一个入口**：

```
pipeline.ps1  →  Search-Knowledge  →  ┌─ local  : data/policy_index.csv（现在）
                                      └─ qianfan: 你配置的 MCP / AppBuilder 端点
```

这样接千帆时**不用碰管线**，只改配置。

---

## 二、目标架构

你说的那个链路，在本项目里对应这样：

```
本地服务 (server.ps1)
   │
   └─ Search-Knowledge
         │
         └─ POST {qianfan_endpoint}        ← 你填的 MCP Server / AppBuilder 检索端点
                │
                ├─ 千帆知识库 MCP Server → 千帆 AppBuilder API（政策/术语/案例）
                └─ 千帆数据库 MCP Server → 订单/政策/话术表
```

**关键点**：MCP Server 由谁提供都行（千帆官方的、你自己写的、第三方网关），
只要它**按下面的契约收发 JSON**，本地服务就能用。

---

## 三、接口契约（这是你唯一需要适配的东西）

### 请求

本地服务会发这样一个 POST：

```http
POST {qianfan_endpoint}
Content-Type: application/json
Authorization: Bearer {qianfan_token}      ← 只有配了 token 才发这个头

{
  "query":    "退货 消费者 救济",       // 检索关键词（由意图自动推导）
  "top_k":    4,                        // 要几条
  "country":  "DE",                     // 客户所在国
  "platform": "amazon",                 // 渠道平台
  "app_id":   "你的 AppBuilder 应用ID",  // 可选
  "dataset":  "你的知识库ID"             // 可选
}
```

### 期望响应

```json
{
  "results": [
    {
      "doc_id":         "ES-TRLGDCU-118",
      "title":          "西班牙商品瑕疵救济顺位",
      "snippet":        "买方主张瑕疵救济时，商家应先修理或更换……",
      "score":          0.87,
      "country":        "ES",
      "platform":       "SCOPE_GLOBAL",
      "effective_date": "2014-03-27"
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `doc_id` | **是** | 引用编号。**会显示给坐席**，是"符合当地政策"的凭证 |
| `title` | 是 | 政策条目标题 |
| `snippet` | 是 | 正文片段（进提示词的上下文） |
| `score` | 否 | 匹配分。缺省按 0 处理，会影响覆盖度判定 |
| `country` | 否 | 缺省 `SCOPE_GLOBAL`。**判覆盖度要用** |
| `effective_date` | **建议填** | 生效日期。没填的话时效过滤无法生效 |
| `platform` | 否 | 缺省 `SCOPE_GLOBAL` |

> ⚠️ **`doc_id` 和 `effective_date` 是合规场景的硬要求。**
> 没有 `doc_id` 就没法引用溯源；没有 `effective_date` 就没法排除已废止的政策。

### 返回字段名不一致怎么办

只改 `engine/knowledge.ps1` 里 `Search-KnowledgeQianfan` 的**映射那几行**，
管线完全不用动：

```powershell
$out += [pscustomobject]@{
  doc_id         = [string]$r.doc_id        # ← 你的字段名不同就改这里
  title          = [string]$r.title
  snippet        = [string]$r.snippet
  score          = [double]$r.score
  country        = [string]$r.country
  ...
}
```

## 四、配置方法

### 方式 A：界面上配（推荐）

网页版 → **设置** → **知识源** → 选「千帆知识库」→ 填端点 → 保存 → 点「测试连接」。

### 方式 B：直接改配置文件

编辑 `hzj-ai-aftersales/config.local.json`：

```json
{
  "model": { "...": "..." },
  "knowledge": {
    "provider":         "qianfan",
    "qianfan_endpoint": "http://127.0.0.1:8080/mcp/search",
    "qianfan_app_id":   "your-appbuilder-app-id",
    "qianfan_dataset":  "your-dataset-id",
    "qianfan_token":    "",
    "timeout_ms":       8000,
    "fallback_local":   true
  }
}
```

改完**重启服务**（界面里改的话是立即生效）。

### 方式 C：调接口

```powershell
$b = '{"provider":"qianfan","qianfan_endpoint":"http://127.0.0.1:8080/mcp/search"}'
Invoke-RestMethod http://127.0.0.1:8799/api/knowledge -Method POST -Body $b -ContentType 'application/json'
```

## 五、字段与接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/knowledge` | 看当前知识源状态 |
| POST | `/api/knowledge` | 改配置（`provider` / `qianfan_endpoint` / …） |
| POST | `/api/knowledge` `{"test":true}` | 连通性自检，返回耗时与失败原因 |

状态返回示例：

```json
{
  "configured": "qianfan",
  "active": "local",
  "active_label": "本地 CSV 知识库",
  "degraded": true,
  "degrade_reason": "千帆知识库检索失败：无法连接到远程服务器",
  "local_ready": true,
  "local_count": 18,
  "qianfan_ready": false
}
```

## 六、降级行为（重要）

**千帆没配好或连不上时，会自动回退本地 CSV，并把原因记录下来。**

| 情况 | 行为 |
|---|---|
| `provider=local`（默认） | 只用本地 |
| `provider=qianfan` 但没填端点 | 回退本地，原因：`未填写 qianfan_endpoint` |
| `provider=qianfan`，端点连不上 | 回退本地，原因：具体的连接错误 |
| `provider=qianfan`，端点通了但没结果 | **不回退**（这是合法结果，可能是真没有相关政策） |
| `fallback_local=false` | 不回退，宁可没有证据 |

**为什么这么设计**：合规场景里"静默返回空"比"明确报错"危险得多 ——
前者会让坐席以为"确实没有相关政策"，后者才知道是链路出了问题。

降级原因会写进分析结果的 `meta.kb_degrade_reason`，界面可以显示出来。

## 七、接的时候建议这么验

1. **先让 MCP Server 用 curl 单独跑通**
   ```bash
   curl -X POST http://127.0.0.1:8080/mcp/search \
     -H "Content-Type: application/json" \
     -d '{"query":"退货 消费者","top_k":2,"country":"DE","platform":"amazon"}'
   ```
   确认返回体符合第三节的契约。

2. **再点「测试连接」**，看耗时和返回样本。

3. **切 `provider=qianfan`**，分析一次，看 `meta.kb_provider` 是不是 `qianfan`、
   `kb_degraded` 是不是 `false`。

4. **对比覆盖度**：本地是 18 条政策，千帆应该覆盖更全。
   看分析结果里的 `retrieval.coverage` 有没有从 `partial` 变 `sufficient`。
