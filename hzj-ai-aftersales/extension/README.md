# 浏览器扩展原型（hzj-ai-aftersales/extension）

> 在客服后台**右侧侧边栏**读取对话 → 生成候选话术 → **一键插入输入框**。
> 零复制粘贴：不用截图、不用切窗口、不用手打。

**首选测试平台：TikTok Shop 商家后台**（理由见文末）。
架构已按多平台设计，Amazon 适配器已占位，后续加平台只需新增一个文件。

---

## 一、3 分钟装起来

浏览器扩展不能像普通程序那样双击运行，要走"开发者模式加载"。步骤如下：

1. **先启动本地服务**（扩展要调它）：
   双击 `hzj-ai-aftersales\启动网页（推荐用扩展，详见README）.bat`，确认窗口里显示"服务已启动"，并**保持这个窗口开着**。

2. **打开扩展管理页**
   - Edge：地址栏输入 `edge://extensions/`
   - Chrome：地址栏输入 `chrome://extensions/`

3. **打开「开发人员模式」**（右上角开关）

4. **点「加载解压缩的扩展」**，选择这个文件夹：
   ```
   C:\Users\26951\Desktop\hzj\hzj-ai-aftersales\extension
   ```
   ⚠️ 选**文件夹本身**，不要选里面的文件。

5. 加载成功后工具栏会出现一个蓝紫色 **AI** 图标。

6. **打开你的客服后台**（TikTok Shop 商家后台 → 消息/聊天页面），
   右侧会自动出现侧边栏。若没出现，点一下工具栏的 AI 图标。

## 一·五、侧边栏显示什么（v0.8）

与网页版工作台对齐，按重要性从上到下：

| 区块 | 内容 |
|---|---|
| **⚠ 高风险案件** | 命中风险时置顶提示「回复前请核对下方政策依据」——**不是"建议转人工"**，因为客户早就在人工手里了 |
| **意图 / 情绪 / 紧急度** | 多标签意图 + 情绪极性/强度 + 紧急度 + 客户国家 + 知识覆盖度 |
| **工单路由（技能驱动）** | 分派组 + SLA，**从 `ecommerce-intent-routing.md` 的表格解析而来** |
| **情绪安抚策略（技能驱动）** | 按情绪强度自动选级，显示处理方式与禁止项，**来自 `customer-reply-craft.md`** |
| **政策依据** | 每条证据的标题、摘要、`doc_id`、适用国家、**生效日期**、匹配分 |
| **命中技能** | 本次按触发词命中的技能名 + 注入的提示词字符数 |
| **候选话术** | ≤3 条，上层客户语言 / 下层中文对照，各带独立复制，**⤵ 一键插入输入框** |

> 政策依据这一块是 v0.8 新加的——扩展之前**完全不展示证据来源**，
> 而"符合当地政策"恰恰是本产品的核心卖点，不展示等于白做。
## 二、怎么用

### 首次使用：校准一下（30 秒，只需做一次）

因为平台的 DOM 结构我无法登录查看，扩展默认用**启发式自动识别**去找对话区。
如果它找得不准（比如把左侧会话列表当成消息、或漏了消息），点侧边栏底部的 **⚙** 手动教它一次：

| 步骤 | 操作 |
|---|---|
| ① | 点 **⚙** → 「拾取消息区」→ 页面变暗进入拾取模式 |
| ② | 鼠标移动到**真正显示聊天记录的那块区域**（包含多条消息气泡的容器），点一下 |
| ③ | 顶部会提示「匹配 N 个元素」，N 是消息条数就对了 |
| ④ | 点 **⚙** → 「拾取回复输入框」→ 点你平时打字的输入框 |

拾取结果保存在**本机浏览器**里（`chrome.storage.local`），不会上传。
平台改版后重新点一次即可，不用改代码。

### 日常使用

1. 侧边栏点 **「读取并生成话术」**，或直接开 **「▶ 自动监听」**
   （开启后对话一有变化就自动分析，不用手动点）
2. 侧边栏会显示：意图 / 情绪 / 紧急度 / 风险 → **≤3 条候选话术**
3. 每条话术上：
   - **⤵ 插入输入框** ← 核心功能，点了直接填进聊天框，你检查一下按回车就行
   - **📋 复制** ← 备用
   - **✓ 采纳 / ✕** ← 记录到数据闭环
4. 右上角可选**目标语言**（英文/西语/中文）和**客户国家**（影响政策检索）

侧边栏底部会显示连接状态。**红灯 = 本地服务没开**。

## 三、⚠️ 我需要你提供什么

**先说结论：不给我任何东西，也能先用起来**（靠自动识别 + 拾取器）。
但要让它**稳定可靠**，我需要下面这些。按重要性排序：

### 1️⃣ 最有用：真实对话区的 HTML 片段（★★★★★）

这是唯一能让我把选择器写准的东西。做法：

1. 打开 TikTok Shop 商家后台的聊天页，进到有真实消息的会话
2. 按 **F12** 打开开发者工具
3. 在 **Elements** 面板里，用左上角的"选择元素"箭头（或直接右键某条消息 → 检查）
   **点中一条消息气泡**
4. 在 Elements 面板里向上找 2~3 层，找到**包着所有消息的那个容器**
5. 右键那个容器 → **Copy → Copy outerHTML**
6. 把复制到的内容发我（**注意脱敏**：把客户昵称、订单号、真实聊天内容替换成占位文字）

> 如果 outerHTML 太大，只给我**结构骨架**也行 —— 保留标签名和 class 名，
> 把文本内容全部删掉。例如：
> ```html
> <div class="chat-list-xxx">
>   <div class="message-item-xxx" data-e2e="msg">
>     <div class="bubble-xxx">TEXT</div>
>   </div>
>   ...
> </div>
> ```

### 2️⃣ 很有用：4 张截图（★★★★）

| 截图 | 用途 |
|---|---|
| 整个聊天页面（能看到消息列表 + 输入框） | 判断整体布局、左右气泡区分方式 |
| 一条**买家**消息和一条**卖家**消息（局部放大） | 识别 class 命名规律、判断左右分栏依据 |
| 输入框区域 | 确定输入框是 `textarea` 还是 `contenteditable` |
| 左侧会话列表 | 避免把会话列表误判成消息列表 |

截图请**打码**客户信息。

### 3️⃣ 有用：确认几件事（★★★）

- **你用的是哪个后台？** TikTok Shop 商家后台 / Amazon Seller Central / Temu 商家中心 / 其他？
  域名是什么（如 `seller-us.tiktok.com`）？
- **聊天界面是弹窗、独立页面，还是嵌在 iframe 里？**
  （如果是 iframe，扩展需要额外配置 `all_frames`）
- **浏览器是 Chrome 还是 Edge？**（影响加载方式和 manifest 细节）
- **输入框打字的语言**：你们平时用英文回，还是先用中文写好再翻译？

### 4️⃣ 可选：真实对话样本 5~10 条（★★）

用来说明客户实际怎么说。**必须脱敏**。这批样本我会拿去做两件事：
- 补进意图识别的关键词库（提升识别率）
- 作为评测集，验证话术质量

## 四、为什么选 TikTok Shop 商家后台做首选

| 理由 | 说明 |
|---|---|
| **目标用户就在这** | 申报书写的核心首批用户是「汉正街云尚国际时尚中心 400 余家服装**跨境直播**商户」——直播商户的主战场就是 TikTok Shop |
| **增速最快** | 跨境电商里增长最猛的渠道，痛点也最集中 |
| **会话结构典型** | 买家/卖家左右分栏 + 底部输入框，是这类后台的通用形态，适配经验能直接复用到其他平台 |

Amazon 排在第二（体量最大但结构差异大），Temu 第三。适配器已为它们预留位置。

## 五、多平台扩展怎么做

新增一个平台 = **加一个适配器文件 + 注册一行**，其余代码完全不动。

```
extension/adapters/
├─ index.js         注册表 + 识别逻辑 + 选择器解析（不用改）
├─ tiktok_shop.js   ✅ 已写
├─ amazon.js        ⏳ 占位，待补真实选择器
└─ generic.js       ✅ 通用兜底（匹配任何页面）
```

新增 `temu.js` 的模板：

```js
const AIH = window.AIH || (window.AIH = {});
AIH.AdapterTemu = {
  id: 'temu',
  name: 'Temu 商家中心',
  verified: false,
  match() { return /seller\.temu\.com$/.test(location.hostname); },
  candidates: {
    messageList: ['选择器候选1', '选择器候选2'],
    messageItem: ['...'],
    inputBox:    ['textarea', '[contenteditable="true"]']
  },
  notes: '待验证'
};
```

然后在 `adapters/index.js` 的 `all()` 里加一行，并在 `manifest.json` 的
`content_scripts.matches` 和 `host_permissions` 里加上域名即可。

> **每条适配器都可以是"未验证"状态而正常工作** —— 因为选择器失效时会自动退到
> 启发式识别，用户也能用拾取器现场学。这是这套架构的关键设计。

## 七、安全设计

| 项 | 做法 |
|---|---|
| **密钥不进浏览器** | 扩展**不接触**任何 API Key。它只调本地服务 `127.0.0.1:8799`，密钥在本地服务侧用 DPAPI 加密保存 |
| **为什么由 Service Worker 发请求** | 内容脚本的 fetch 会带**宿主页面**的 Origin，本地服务就得对任意网站开放跨域——那等于让所有网页都能调 `/api/clipboard`。改由扩展 Service Worker 发请求，Origin 是 `chrome-extension://`，本地服务只放行扩展来源 |
| **本地服务 CORS 已收紧** | 从 `Access-Control-Allow-Origin: *` 改为白名单：只放行 `chrome-extension://` 和本机页面。其他网站的请求会被浏览器直接拦掉 |
| **选择器配置只存本机** | 存在 `chrome.storage.local`，不上传 |
| **不读取无关内容** | 只在匹配的域名注入；手动注入其他站点需你主动点图标 |

## 八、已知限制

| 限制 | 说明 | 后续方案 |
|---|---|---|
| **TikTok 选择器未验证** | 我无法登录你的后台查看真实 DOM | 你给我 HTML 片段，我换成准确选择器；或用拾取器现场学 |
| **启发式识别可能不准** | 复杂页面可能把会话列表误判成消息列表 | 用拾取器校准一次即可长期有效 |
| **iframe 内嵌聊天未处理** | 若聊天在 iframe 里，需要加 `all_frames: true` | 确认后我加上 |
| **输入框插入依赖框架兼容性** | 已处理 React/Vue 的原生 setter 问题，但个别自研编辑器可能仍失败 | 失败时用「复制」按钮兜底 |
| **Amazon 适配器是空壳** | 只有结构，没有验证过的选择器 | 第二优先级补 |
| **未做发送动作** | 只插入，不自动点发送 —— **故意的**，人工确认后才发 | 保持 |

> 最后一条是刻意的设计：**扩展永远不替你发送消息**。
> 合规要求人工确认，且自动发送一旦出错代价很高。

## 九、JS 校验（本项目没有 Node）

扩展写完没法用 Node 跑语法检查，所以做了一个替代工具：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File hzj-ai-aftersales\tools\check-js.ps1
```

它用状态机扫一遍所有 JS，检查括号配对、字符串/模板字符串/块注释/正则字面量是否闭合，
并校验 manifest 里引用的文件是否都存在。当前状态：**全部通过**。

抓不出类型和语义错误，但手写大文件时的低级错误基本都能拦住。
真正的语法验证在你加载扩展时由浏览器完成——如果加载失败，扩展页会直接报出文件名和行号。
