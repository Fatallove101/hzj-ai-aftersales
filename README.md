# 跨境销售 AI 话术助手

> **给跨境销售客服坐席用的 AI 话术副驾。**
> 售前咨询、售中跟进、售后纠纷 —— 从读懂客户到给出合规话术，一个侧边栏全解决。

基于 **百度千帆 AppBuilder** 构建：1 个主控 Agent 编排 6 个专业子 Agent，
配合可插拔知识库与可执行合规规则库。

---

## 一、我们要解决什么问题

跨境销售客服每天卡在三座山上：

| 山 | 具体表现 |
|---|---|
| **语言关** | 客户用德语/西语/日语/英语发来长段话，坐席看不懂，只能复制去翻译软件，来回切窗口 |
| **政策关** | "14 天无理由退货"是欧盟的、"重大故障可主张换货"是澳洲的、日本对退款措辞有特别要求 —— 坐席不熟，一句话说错就可能违规或吃差评 |
| **效率关** | 一个坐席同时开 5~10 个会话，每条都要重新组织语言、查政策、想措辞，回复慢、口径不统一 |

**结果是**：响应慢、口径乱、新人上手难、合规风险靠运气。

---

## 二、这个产品是什么

**一个挂在客服后台右侧的话术副驾。**

它做四件事：

```
读懂客户  →  查准依据  →  生成话术  →  一键插入
（翻译+意图+情绪）  （政策+术语+案例）  （多风格候选+合规校验）  （写进回复框）
```

坐席点一下就能把话术填进回复框，**看一眼、改一改、发出去**。

### 覆盖售前 + 售后全链路

| 阶段 | 典型场景 | 工具怎么帮 |
|---|---|---|
| **售前** | 尺码咨询、材质成分、库存交期、能否议价、跨境运费与关税 | 检索商品与政策知识 → 生成专业答疑话术（不夸大、不作绝对化承诺） |
| **售中** | 催发货、改地址、加急、合并订单 | 结合物流规则与平台时效 → 生成安抚+进度说明 |
| **售后** | 色差/做工/尺码不符、退换货、退款时效、物流丢件、差评沟通 | **核心场景**：检索该国法定权利与平台规则 → 生成合规话术并标注依据 |
| **纠纷升级** | 平台介入、拒付、法律风险、知识无依据 | 强制标「高风险案件」，提示先核实再回复 |

### 不限定行业

虽然源于**服装类目**的实战需求（色差、起球、缩水、做工是服装跨境的高发雷区），
产品设计**不依赖任何特定品类**：

- 知识库、合规规则库、术语库都是**可替换的数据文件**（CSV），换品类只换数据
- 7 份 Agent 提示词里的品类假设已抽成变量
- 意图体系覆盖的是**通用销售服务意图**（退款/换货/物流/质量/尺码/评价/复购/产品咨询/支付/清关/发票/服务投诉）

**适用于**：服装、3C、家居、美妆、母婴、户外、宠物用品等任何跨境电商品类。

## 三、目标人群

| 人群 | 为什么需要 |
|---|---|
| **中小跨境卖家（1~20 人客服团队）** | 没有合规团队、没有培训体系，新人上手全靠老带新；请不起外语客服 |
| **多平台铺货卖家** | 同一套话术要在 TikTok Shop / Amazon / 独立站之间复用，口径容易乱 |
| **跨境代运营 / 客服外包公司** | 坐席流动率高、培训成本高，需要把"老手的经验"沉淀成工具 |
| **品牌出海团队** | 对品牌调性和合规有要求，不能容忍客服随口承诺 |

**共同特征**：要面对**多语言 + 多国法规 + 多平台规则**，但**没有对应的人力储备**。

## 四、落地价值

### 对坐席（直接使用者）

- **不用切窗口**：翻译、查政策、想措辞都在一个侧边栏里
- **不用背法规**：政策依据随话术一起给出，点开就能看原文出处
- **不用怕说错**：合规闸门**在服务端执行**，违规话术根本不会出现在候选里
- **新人也能上手**：从"不敢回"到"照着改一改就能发"，学习曲线大幅缩短

### 对团队（管理者）

- **口径统一**：同一国家、同一场景，所有人拿到的是同一套依据
- **风险可控**：规则库可配置（内置 30 条 + 支持自定义禁用表述），命中即拦截
- **经验沉淀**：采纳 / 修改 / 忽略都会写回日志，**人工修改幅度**能反映话术质量，形成"生成→使用→改进"的闭环
- **合规留痕**：每条话术都能追溯到 `doc_id` 和生效日期

### 可量化的观测指标（由产品自带的数据闭环产出）

产品从第一天就在记录这些，**试点后即可拿到真实数字**：

| 指标 | 含义 |
|---|---|
| 话术采纳率 | 候选话术被直接采用的占比 |
| 人工修改幅度 | 采纳时被改写了多少（用编辑距离算），越低说明话术越贴合 |
| 首次响应耗时 | 从读到客户消息到坐席发出回复的时间 |
| 合规拦截率 | 被规则拦下的候选占比 |
| 高风险案件占比 | 需要人工额外核实的比例 |

> **诚实说明**：以上是产品**能测**的指标。**具体数值需要真实试点数据**，
> 我们不在文档里编造提升百分比。

## 五、定位澄清（很重要，别理解错）

本工具 **不是「AI 客服」**，也 **不是**"AI 答不了就转人工"。

真实业务链路是：

```
别的 AI 客服先接待 → 解决不了转人工 → 人工坐席用本工具生成话术 → 人工确认后回复客户
                                          ↑ 我们在这里
```

所以：

- **我们的用户是坐在工位上的人工客服**，不是终端消费者
- **我们的产出是给人工用的话术建议**，工具**永远不直接给客户发消息**
- 界面上没有"建议转人工"，只有「**⚠ 高风险案件 · 回复前请核实**」
- 对话里会混着**前面 AI 客服说过的话**，必须分得清（否则人工会和 AI 自相矛盾）
- **"符合当地政策"是核心卖点** —— 政策依据面板和分析面板同级突出

**为什么不做成"直接对客户说话"的机器人？**
跨境销售场景里，一句话说错就是法律风险和品牌损失。
让 AI 直接对客户输出、无人把关，在**法规差异大、纠纷金额高**的跨境场景下不可接受。
**AI 负责把活干到 90%，人负责最后那 10% 的判断** —— 这是产品的核心取舍。

## 六、为什么能落地（不是概念演示）

| 顾虑 | 我们的做法 |
|---|---|
| "大模型会胡说" | **合规闸门是确定性正则的**，不靠模型自觉；`reject` 的话术不返回给前端 |
| "没有依据的话不敢用" | 政策话术必须能对应到知识库里的 `doc_id`，且带生效日期 |
| "接不上我们的系统" | 三种接入方式：浏览器扩展（零改造）/ 网页版工作台 / HTTP API |
| "平台改版就读不到了" | 五种读取方式（页面/剪贴板/窗口直读/读屏OCR/手动），外加**拾取器现场校准** |
| "模型挂了就废了" | **全链路可降级**：模型不可用时自动回退本地规则引擎，功能不中断 |
| "数据安全" | 密钥 DPAPI 加密只存本机、接口永不回显、日志脱敏；**本地服务 CORS 白名单**只放行扩展 |
| "换品类要重做" | 知识库/规则库/术语库都是 CSV 数据文件，换品类只换数据 |

**当前状态**：本地演示可运行（零依赖，双击即用），已通过 **10 项自动化自检**。

## 不想每次都手动启动服务？装成开机自启

浏览器扩展**没法启动本机进程**，所以本地服务必须有人拉起来。
如果嫌每次开机都要双击 bat 麻烦，装一次自启即可：

```powershell
cd hzj-ai-aftersales
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1 -Install
```

装完之后：**登录 Windows 时服务自动在后台静默启动**（不弹窗口、不占任务栏），
打开任何网页 + 扩展都能直接连上。

```powershell
# 看当前状态（有没有装、服务在不在跑）
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1

# 不想要了就卸掉
powershell -ExecutionPolicy Bypass -File tools\autostart.ps1 -Uninstall
```

> 自启的命令带 `-NoBrowser`，所以开机时**不会**弹浏览器窗口 —— 想看页面自己双击 bat。

## 核心功能

### 五种读取对话的方式

| 按钮 | 原理 | 适用 |
|---|---|---|
| **页面** | 直读网页 DOM | 普通网页，**100% 精确，首选** |
| **剪贴板** | 读系统剪贴板 | 任何软件里选中文字 `Ctrl+C` 后点它 |
| **窗口** | UI Automation 直读窗口文字 | 桌面客户端（**不走 OCR，无识别误差**） |
| **读屏** | 截图 + Windows OCR | DOM 读不到时（Canvas 自绘界面、图片里的字） |
| **手动** | 自己粘贴 / 输入 | 任何来源：第三方系统、抄来的、口头转述 |

**页面 vs 读屏是互补的，不是重复的**：页面准但只能读网页；读屏有误差但**任何界面都能用**。
微信文件传输助手那种自绘界面，DOM 读不到，只能靠读屏。

### 三框工作台

| 框 | 内容 |
|---|---|
| **① 客户对话** | 按说话人分色的对话气泡（客户/AI客服/人工客服）+ 中文对照；读取源按钮都在这个框的标题栏 |
| **② 候选话术** | ≤3 条候选，中外双语，带合规标记；「**换一批**」重新生成 |
| **③ 详情** | 读取设置（国家/回复语言）、当前平台、意图情绪、政策依据、命中技能（可折叠） |

### 其它

- **理解客户**：14 类意图识别、情绪强度、紧急度分级、风险标记
- **检索知识**：20 条各国政策（ALL/EU/US/DE/ES/GB/AU/FR/IT/JP）+ 46 条服装跨境术语，按国家/平台/生效日期过滤
- **生成话术**：≤3 条候选，五种风格（安抚致歉 / 专业答疑 / 营销促单 / 纠纷调解 / 合规告知）
- **合规闸门**：真实执行 30 条规则的正则校验，`reject` 的话术**永不进入最终输出**
- **修改后采纳**：改中文 → **外文自动重新翻译** → 直接插入输入框（保证内外记录一致）
- **高风险判定**：命中平台介入 / 拒付 / 法律风险 / 知识无依据等条件时强制标高风险
- **数据闭环**：采纳 / 修改 / 忽略写回日志，统计采纳率与人工修改幅度
- **设置页**：生效模式、知识源（本地 CSV / 千帆）、自定义禁用表述（含误杀预警）
- **API Key 安全**：DPAPI 加密存储、接口永不回显、不进 git
- **日志脱敏**：请求体落盘前过 `Protect-LogBody` —— 密钥类字段整值抹掉、
  正文类字段只留长度不留内容、任何 `bce-v3/` 串一律打码
  > ⚠️ **v0.33.0 之前这条是假的**：`Write-ReqLog` 会把原始请求体整行写进
  > `hzj-ai-aftersales\logs\requests.log`，保存密钥那次请求把**密钥明文**落了盘，
  > 分析请求还把**客户对话原文**落了盘（实测 118 行）。
  > 已修 + 已删除存量日志。详见 CHANGELOG 或 commit `v0.33.0`。

## 接上千帆模型

### 1. 复制配置

```powershell
cd hzj-ai-aftersales
copy config.example.json config.local.json
```

编辑 `config.local.json`：

```json
{
  "model": {
    "provider": "qianfan",
    "endpoint": "https://qianfan.baidubce.com/v2",
    "model": "ernie-4.5-turbo-128k",
    "timeout": 90
  }
}
```

> **`endpoint` 填基址即可**，代码会自动补 `/chat/completions`。
> 填完整路径也能用（见 `engine/llm.ps1` 的 `Resolve-ChatUrl`）。

### 2. 存密钥

```powershell
powershell -ExecutionPolicy Bypass -File tools\set-api-key.ps1
```

密钥用 **Windows DPAPI（CurrentUser）加密**后存到
`%APPDATA%\hzj-agent\credential.dat`，**明文不落盘、不进 git、接口永不回显**
（只返回 `has_key` 和一个 8 位 SHA256 指纹）。

也可以在扩展设置页 ⚙ 或网页版「设置」里直接填。

### 3. 核对请求形状

```powershell
powershell -ExecutionPolicy Bypass -File tools\test-model.ps1 -DryRun
```

只打印请求体形状，**不发请求、不打印密钥**。确认无误后再去掉 `-DryRun` 真发一次。

### 4. 重启服务

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File server.ps1 -Port 8799
```

## 安全设计

- **API Key**：Windows DPAPI 加密，只存本机，接口永不回显，不进日志，`config.local.json` 已 gitignore
- **本地服务 CORS 白名单**：只放行 `chrome-extension://` 来源 + 本机页面，
  任意网站读不到剪贴板/窗口文字
- **扩展通过 Service Worker 发请求**（不在 content script 里直连），
  这样服务端才能按扩展来源做白名单
- **合规闸门在服务端执行**：`reject` 的话术不返回给前端，不是靠前端自觉

## 改代码前必读

1. **所有 `.ps1` 必须存成 UTF-8 with BOM**。PowerShell 5.1 没有 BOM 就按 GBK 解码，
   中文变乱码 → 引号断裂 → 语法错。用 `tools\check-bom.ps1` 检查。
2. **别用 `\"` 转义双引号** —— PowerShell 里不合法。用单引号 here-string（`@'...'@`）。
3. **`Contains()` 做插入锚点不可靠** —— 用精确锚点或行号，
   并**确认替换真的生效**（打印替换前后的行数/内容）。
4. **改完一定跑全量自检**，尤其是渲染冒烟和路由检查。
5. **反向验证**：新加一条检查后，故意把 bug 还原回去，确认检查**真的会失败**。
   不会失败的检查比没有检查更糟 —— 它给虚假的信心。
