## 二、架构一句话概括

> **一个主控 Agent 负责"串流程、汇总、决定转不转人工"，六个子 Agent 各管一段：翻译 → 意图情绪 → 查询改写 →（检索）→ 话术生成 → 合规校验；数据闭环 Agent 在回复之后异步跑，反推知识库缺口。**

```
                         ┌──────────────────────────────────────────────┐
   海外买家消息  ──────►  │            主控 Agent (Orchestrator)          │
   多语言原文            │  串流程 / 汇总结果 / 决定是否转人工 / 最终 JSON │
                         └───┬───────┬───────┬───────┬───────┬──────┘
                             │       │       │       │       │
                    ┌────────▼──┐ ┌──▼─────┐ ┌▼────────┐ ┌▼────────┐ ┌▼────────┐
                    │ 翻译Agent │ │意图情绪│ │查询改写 │ │话术生成 │ │合规校验 │
                    │           │ │ Agent  │ │ Agent   │ │ Agent   │ │ Agent   │
                    │translated │ │intent, │ │queries, │ │candidat-│ │pass /   │
                    │_text      │ │emotion,│ │filters  │ │es (≤3)  │ │revise / │
                    │           │ │urgency │ │         │ │         │ │reject   │
                    └───────────┘ └────────┘ └────┬────┘ └─────────┘ └─────────┘
                                                  │
                                    ┌─────────────▼──────────────┐
                                    │  千帆知识与数据层（并行召回） │
                                    │ RAG知识库 │ 结构化数据库 │ 合规规则库 │
                                    └────────────────────────────┘

   ─────────── 以上为「同步主链路」，目标 P95 ≤ 6s ───────────

                         ┌──────────────────────────────┐
   客服采纳/修改/忽略 ──► │      数据闭环 Agent（异步）    │ ──► 优化建议 / 知识库缺口
   客户满意度反馈        │ 记录采纳-修改-忽略-满意度       │
                         └──────────────────────────────┘
```

## 四、快速上手 3 步（在千帆控制台）

1. **建知识库与数据库**：按 `03-知识库与数据层设计.md` 建 5 个 RAG 知识库 + 1 个结构化数据库（13 张表）；
   种子数据先用 `data/` 里的 CSV 跑通，再替换成真实商户数据。
2. **建 7 个 Agent**：把 `prompts/` 里的提示词逐条粘贴，按 `schemas/` 配好结构化输出；
   在工作流里用 LLM 节点 / Agent 节点承载，用变量串起来。
3. **串成工作流并发布**：按 `04-千帆AppBuilder搭建实施手册.md` 第 3 节的连线图连节点，
   跑通后再按第 6 节发布成 API，接到自建 Web 坐席工作台。

> 平台入口：<https://console.bce.baidu.com/qianfan/studio/officialAppCenter>
> 建议先在「官方应用中心」找智能客服/话术类模板做底座，再替换为本文档的 7 Agent 结构，可省一半搭建时间。

## 五、三条必须守住的设计红线

1. **合规先行**：话术生成后必须过合规校验 Agent，`decision = reject` 的候选话术**永远不进入**最终 JSON 的 `final` 字段。
2. **人工兜底**：主控 Agent 在任何 `urgency = critical`、`decision = reject` 全量、或检索覆盖度为 `insufficient` 时，必须 `need_human = true`，不得硬答。
3. **可追溯**：每条对外话术都必须带 `cited_evidence`（政策/案例/产品来源），客服工作台上可见，方便复盘与担责。
